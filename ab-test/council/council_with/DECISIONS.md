# Decisions — Build the order-details parser for Dallal, an Instagram DM sales assistant for Iraqi cash-on-delivery shops: Python package dallal_parser with parse_order(text) -> dict (name, phone +9647XXXXXXXXX, governorate English name, address, plus whatever else is needed), handling Iraqi Arabic, English and mixed messages, with tests, output in ./output

Council: Skeptic (red team), User advocate, Builder (pragmatist), Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions, Quality engineer · stakes standard · plan v3

- **D1** Deterministic stdlib-only package, small pure stages, public validators.
- **D2** `needs_followup` also fires on `governorate_inferred`; reason `ambiguous_grouping` (O19, O12).
- **D3** aliases folded at import by the same function, Kurdish spellings explicit, reachability test (O6).
- **D4** explicit grouping rules (≥8-digit groups never joined, no 1-digit inner groups, prefix groups always part of the number, ambiguous multi-group + stray short group → reject), ≥5-digit neighbours tolerated, Latin-glued ≥7-digit runs accepted (O1, O5, O9, O12, O17, O26).
- **D5** no automatic ال-stripping; NAME_COLLISIONS gating; عبد/ابو/ام guard; اليرموك/المنصور out of Tier C; Tier-A phrases; more exclusions (O7, O11, O18, O23, O24).
- **D6** Tier A+B share a rank with segment-start precedence; Tier C low; Tier C counts in conflicts; more reference words (O10, O19, O22, O23).
- **D7** type-checked labels, governorate+area labels, Arabizi digit rule, ≥2 candidates → nearest before address + low, larger noise lexicon, `عبد X` as one token (O2, O8, O20, O25).
- **D8** governorate-label remainder goes to the address (O8).
- **D9** Robustness, performance, observability.
- **D10** invariants rewritten to match the plan; shuffle only on `shuffle_safe`; holdout frozen; new trap tests AT22–AT25 (O3, O13, O14, O21).
- **D11** README as the integration contract.

## How objections were handled
- O1 [major] (Builder (pragmatist)) D4's 'partition at group boundaries into valid numbers + short groups' rule turns the 10-digit typo '0770123456 7' into the valid mobile +9647701234567. This contradicts AT14 ('0770123456 7' -> phone None) and is the stray-digit fabrication the Skeptic flagged as a blocker. D4 also doesn't say which partition wins when several are valid. → D4 grouping rules (a)-(d): >=8-national-digit groups never joined; prefix groups part of number; fewest leftovers tie-break; implemented in phones.py, '0770123456 7' -> invalid.
- O2 [major] (Builder (pragmatist)) The digit rules for names contradict each other: the D7 name rule says 'no digits' but allows Arabizi '3li 7sen'; AT16 expects the name '3li 7sen'; the D10 fuzz invariant says 'no digits in name'. Whichever wording the implementer follows, a test fails, and we lose build time arguing it out again mid-build. → D7/D10: no standalone digit tokens; digits allowed only in tokens with Latin letters (3li 7sen ok).
- O3 [major] (Builder (pragmatist)) The fuzz invariant 'shuffle-stable phone/governorate' cannot hold for corpus messages with two phones or two governorates. D4 picks the first valid phone and D6 says 'within a tier, the first occurrence wins', so shuffling lines legitimately changes the primary phone or governorate. D10 explicitly includes two-phone cases in the corpus that the 500 variants are built from. → D10: shuffle stability only for shuffle_safe cases; otherwise set(phones) stable.
- O4 [major] (Builder (pragmatist)) pytest is unavailable here. The plan now uses unittest.TestCase with the command 'python3 -m unittest discover -s tests', which resolves this. → Already resolved: unittest.TestCase + python3 -m unittest discover.
- O5 [minor] (Builder (pragmatist)) The rule 'a digit glued to Latin letters is Arabizi' will drop numbers typed as 'phone07701234567' or 'mobile:07701234567' without the space, which are plausible in English-label DMs. The result is phone None and an unnecessary re-ask. This is low harm because it fails safe. → D4: runs of >=7 digits glued to Latin letters are candidates (mob07701234567); only 1-2 digit glued groups are Arabizi.
- O6 [major] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) Kurdish spellings folded by D3 do not equal the Arabic aliases, so AT16 (هەولێر → Erbil) fails unless aliases are folded by the same function at import. → D3: aliases stored in natural spelling, folded at import by the same fold(); Kurdish spellings explicit; reachability test.
- O7 [major] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) Common Iraqi given names and name parts are also qadha or governorate aliases: عبد الخضر/خضر (الخضر, Muthanna), عبد الحمزة/حمزة (الحمزة, Qadisiyah), قاسم/ابو القاسم (القاسم, Babil), and the surname الرفاعي (الرفاعي, Dhi Qar). Under D5's prefix rule and D6's first-occurrence rule, the name line (usually line 1) gives a wrong governorate candidate and the name is rejected for containing a gazetteer hit. This is the wrong-but-confident or lost-name failure the charter names. → D5: token after عبد/ابو/ام/بن/بنت/آل never a place; الخضر/الحمزة/القاسم/الرفاعي in NAME_COLLISIONS gating; AT22.
- O8 [major] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) Labels bind by shape only. 'رقم' at segment start in address text ('رقم الدار 7') is taken as a phone label, and the area written after a governorate label ('المحافظة: البصرة الجزائر', the common reply to the Iraqi prompt 'المحافظة والمنطقة') is dropped. The result is a usable address lost and address marked missing, or a wrong follow-up question. → D7: type-checked label binding; governorate+area labels; D8: governorate-label remainder prepended to address; AT24/AT25.
- O9 [minor] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) D4's partition rule accepts '0770123456 7' (10+1 groups joined into a valid 11-digit number with confidence medium), but AT14 expects None. The spec contradicts itself. → Same as O1: D4 rules (a)/(b) reject '0770123456 7'.
- O10 [minor] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) Given names that are also governorate names (ميسان, نينوى, نجف), and strict Tier A over Tier B, turn correct DMs into follow-ups: 'ميسان حسين\nبغداد زيونة' → Maysan with low confidence and name None. → D6: Tier A and B share one rank with segment-start precedence; name-collision words gated (D5).
- O11 [minor] (Domain expert — Iraqi cash-on-delivery e-commerce logistics and Iraqi Arabic dialect / phone / address conventions) The Tier C phrase 'بغداد الجديدة' contains the Tier A name بغداد. Separately, اليرموك (also a major Mosul neighbourhood) and العامرية (also عامرية الفلوجة in Anbar) can give a medium-confidence wrong governorate, which counts against the D10 confident-wrong gate. → D5: Tier-A phrases (بغداد الجديدة) resolve explicit/high; اليرموك dropped; عامرية الفلوجة -> Anbar phrase.

- O18 [major] (Skeptic (red team)) With ال optional, Tier B/C aliases match common Iraqi first names and surnames (حمزة, خضر, منصور, امين, غدير, رانية, سوران, الرفاعي).
