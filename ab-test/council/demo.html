What the council did with one important project

The prompt: "This is a big, important project for me… build the order-details parser for Dallal", a Python package that turns Iraqi Instagram DMs into a clean cash-on-delivery order: name, phone, governorate, address. Five specialist agents planned it, argued about it, had it built, and reviewed the real result twice. Everything below comes from that run's own records.

How the council worked

  1. CharterGoal turned into checkable acceptance tests, a case format and a 90% target.
  2. 5 seats proposeEach one alone, without seeing the others. They wrote 151 cases between them.
  3. Seal the holdout61 cases go to the builder; 90 stay hidden for scoring.
  4. Debate27 objections with evidence; plan v1 → v2; 12 decisions.
  5. One builderA separate agent builds from the decisions and the 61 dev cases.
  6. ScoreSealed holdout 90/90, dev 61/61.
  7. Review pass 15 seats test the real package: 37 fresh cases, 31 findings.
  8. Review pass 240 more fresh cases (39 pass before fixes), 19 findings.
  9. GateNo open blocker or major, acceptance passing, target met → ship.

Hidden tests, cost, and what it means

On a well-defined coding task, Claude alone is already near the top, and it varies between runs (91.9 and 97.5 on the hard set). The improved council scored highest on the hard set and matched the single agent elsewhere, at about six times the cost.

Its own sealed score (100%) was a little more optimistic than the truly unseen tests (98.4–99.1). The skill now says so: use the light mode for clear tasks, and the full council when inputs are messy, the domain is unfamiliar or mistakes cost money.
